# Decisions

One dated line per stack choice, scope cut or deferral. What · why · the honest interview framing. Newest at the bottom.

- **2026-09-16 D-001** pnpm workspaces with two apps (`apps/web`, `apps/server`) and a plain `shared/` folder aliased from both tsconfigs · same shape as `giglist`; a third package to hold one 30-line file is packaging for its own sake · "client and server share one ordering function and one schema, nothing else".
- **2026-09-16 D-002** `pg` directly, no ORM · six tables, about ten statements, `schema.sql` is the migration · "I wrote the SQL; an ORM would have hidden the version-check `WHERE` that the whole conflict story depends on".
- **2026-09-16 D-003** CSS Modules over styled-components · styled-components entered maintenance mode in 2025 and runtime CSS-in-JS is where the ecosystem moved away from; the design's tokens are CSS variables on `data-theme`, which is CSS Modules-native · "I chose CSS Modules because styled-components is no longer actively developed; I'd pick it up in a day on a codebase that uses it".
- **2026-09-16 D-004** `tsx watch` + `vite` for dev, `esbuild` for the server bundle · no ts-node, no nodemon · n/a.
- **2026-09-16 D-005** GraphQL Code Generator `client` preset · typed documents, no hand-written domain types · "the schema is the shared contract".
- **2026-09-16 D-006** Node 22, ESM everywhere · native `randomUUID`, `scrypt`, `structuredClone` · n/a.
- **2026-09-16 D-007** Vitest for `ordering.ts`, `moves.ts` and `replay.ts` (pure, unit) plus one integration file `cards/policy.test.ts` against the local Docker Postgres · test where bugs are expensive and manual checking is slow: both review rounds found their worst bugs in the server policy, and re-running the GraphiQL checklist by hand after every server change is slower than a test · "unit tests for ordering and replay, an integration test for the conflict and idempotency rules against real Postgres".
- **2026-09-16 D-008** Render starter web service + **Neon free Postgres** (or Render basic Postgres, paid), auto-deploy on `main` · always-on web so the demo never cold-starts; Render's free Postgres is deleted after 30 days, which could land before the interview, so it is never used · "single instance by design, which is why there is no Redis".
- **2026-09-16 Scope** Account auth, card-level presence and the phone layout are Milestones 8–10, after the core demo · they close no JD gap that Milestones 1–7 don't · "built the sync mechanics first; auth is additive and came after".
- **2026-09-16 Scope** Conflict policy split: moves are last-write-wins, text edits are version-checked optimistic concurrency · a shared version counter let a drag fake a text conflict · "two policies, each named correctly; no CRDT because two people rarely type in the same title at once on a kanban board".
- **2026-09-16 Design** Sync-log row wording changed from "server wins (updatedAt)" to "version mismatch · yours dropped"; header latency pill made optional · design follows plan on mechanics.
- **2026-09-16 D-009** Card ids are generated by the client (`crypto.randomUUID()`) and passed to `createCard(id)` · a card created offline is referenced by later queued ops; server-assigned ids would make every one of them fail with CardGone on replay · "client-generated ids are what make offline creation composable with offline edits".
- **2026-09-16 D-010** GraphQL Code Generator runs for the server too (`typescript` + `typescript-resolvers` → `apps/server/src/gql/`) · untyped resolvers would violate strict TypeScript from day one · "one schema, generated types on both sides".
- **2026-09-16 D-011** Session cookie is `httpOnly`, `sameSite: 'lax'`, `secure` outside development, signed with `COOKIE_SECRET`, 1-year `maxAge` · defaults a security reviewer will ask about; `lax` is enough because the app is single-origin · n/a.
- **2026-09-16 D-012** One `version` per card, not per field · a title edit and a description edit on the same card within the same second will conflict; that is rare on a kanban card and per-field versions would double the schema surface · "field-level versions were the next step I chose not to take; CRDTs the one after that".
- **2026-09-16 D-013** Input limits and one rate limit · `title` ≤ 200 chars, `description` ≤ 5 000, `displayName` ≤ 40, enforced in the resolvers; `@fastify/rate-limit` on the four HTTP session mutations only · a public, editable demo URL will get poked · n/a.
- **2026-09-16 D-014** Structured logging through Fastify's built-in pino; `console.*` is banned in both apps · the sync log is the client's observability surface, pino is the server's · n/a.
- **2026-09-16 D-015** Offline queue parks each operation with its Apollo observable open and replays in order with `baseVersion` **rebase**; earlier plan said coalesce · completing an observable early destroys the optimistic layer and gives the caller a fake result, while coalescing leaves dropped ops with live observables to fake-complete; rebase keeps every promise honest and still removes self-conflicts · "offline edits replay in order; each result rebases the ones behind it, the same idea as a git rebase on a per-card version".
- **2026-09-16 D-016** `Board.cards` is one flat list in the schema and the Apollo cache; columns are derived on the client by `columnId` + `position` · per-column lists would need list surgery on every move (optimistic, result and event), a flat list needs it only on create and delete · "the cache mirrors the table, the view derives the columns".
- **2026-09-16 D-017** `db:reset` runs `psql` inside the Postgres container; `schema.sql` begins with `drop schema public cascade` · no local `psql` in the fresh-clone path, and the same file is the integration test's fixture · n/a.
- **2026-09-16 D-018** Headless Chromium via Playwright, installed in Claude's scratch directory and never in the repo, drives the running dev server for every milestone's Verify step in addition to Adam's two-window manual check · the first two drag-and-drop "fixes" were guesses without a browser and both missed; one scripted drag found the real cause (dnd-kit needs DragOverlay across containers) · n/a.
- **2026-09-16 D-019** Every session mutation (guest start, sign-up, sign-in, sign-out) terminates the graphql-ws socket so it reconnects; the retry backoff starts at 250 ms instead of graphql-ws's 1–4 s · Mercurius resolves the socket context once at `connection_init` from the upgrade request's cookie, so a session created or upgraded afterwards is invisible to that socket; the client cannot re-send a cookie over an open socket · "auth upgrades the session row in place; the socket simply reconnects to read it".
- **2026-09-16 D-020** After the subscription's first event (our own `PresenceChanged` join) the client refetches `board(slug)` once · events published between the initial board query and the subscription start were lost, which the live run reproduced; the join event is the only reliable "subscription is live" signal · "one extra board query per page load buys a gap-free start".
- **2026-09-16 D-021** MobX 7 spells the shallow annotation `observableShallow`; the task list's `observable.shallow` is the MobX 6 name · MobX 7 rejects the old spelling at runtime · n/a.
- **2026-09-16 D-022** Rename drafts live in a module-level map keyed by card id, and Delete/Backspace on a focused row deletes it · a card a peer moves mid-edit remounts in its new column and would lose the draft; the Milestone 6 verify needs a delete before the panel exists in Milestone 7 · n/a.
- **2026-09-16 D-023** `Viewer` and `Subscription.boardEvents` carry explicit cache merge policies (`merge: true`, `merge: false`) · Apollo replaces id-less objects wholesale, so a boards-only query dropped `viewer.session`, and each subscription event warned about replacing the last · n/a.
- **2026-09-16 D-024** The phone move sheet is a long-press (500 ms, no movement) implemented by event delegation on the board, not a dnd-kit sensor · dnd-kit's delay constraint starts a drag, the artboard wants a sheet; one timer and one `<dialog>` cover it · n/a.
- **2026-09-16 D-025** No membership/ownership table exists for who can be assigned a card or where labels live beyond the board they were created on · out of scope for a link-based, no-permissions demo (see Non-Goals: "No orgs, roles or permissions"); any session visible to a board (connected or a past editor) is a valid assignee, and labels are simply scoped to `board_id` · "assignment and labels follow the same no-permissions model as everything else — anyone with the link can set them".
- **2026-09-16 D-026** Card detail fields (priority, due date, assignee, labels) added post-launch on user feedback, not in the original milestone plan · the shipped card only held title/description, which read as too thin for a real detail view once Milestone 7's panel existed to show it in · "built the sync mechanics and the designed UI first per the plan, then extended the domain model once the UI had somewhere to put more fields".
